# Inkloom AI — Implementation Plan

## Goal, constraints, and delivery boundary

Preserve the already-working no-login DemoWear demo; do not recreate the project or disrupt its existing workflow. The three final-round features (reviewer-feedback learning, Admin evidence-library retrieval, and OCR/logo checks) are already delivered. The current request expands the active scope to fix reproducible code defects and complete the previously planned Evaluation, Audit/Status, and Judge-usability/accessibility roadmap items plus push-test CI. Keep the existing text/PDF/image → review → history/dashboard/PDF workflow working, preserve the textile-led design, and report genuine limitations honestly.

The current Webdev project and Manus-managed repository remain canonical. This request does not authorize GitHub transfer, Render deployment, secret entry, or another public release. Do not write test data to production: pytest must use isolated temporary SQLite files, and public smoke checks must remain read-only. Additive schema changes preserve existing tables and rows. Do not add authentication or change the login-free demo; roles remain simulated. Only working features may be claimed.

## Implementation approach

1. **Core stabilization commit:** prevent a second Apply fix from using stale finding offsets after the first text change (disable Apply fix until recheck); make “Load demo data/brand” non-destructive and confirm the separate Reset action; reject overlong extracted PDF text with a clear message instead of silently truncating; validate case-insensitive banned-term uniqueness on update and return a friendly conflict rather than a database error. Add regression coverage and save the requested `fix: core workflow stabilization` commit before feature work.
2. **Persistence and migration:** keep SQLAlchemy + SQLite and preserve all current tables/data. `create_all` adds new tables; an idempotent startup migration adds only missing nullable/defaulted columns to existing `drafts` and `revisions` (including unused `assets`, sample/title metadata, guideline-version and score snapshots). Never drop/recreate a user table. Add new tables for guideline state, AI cache/usage, per-IP rate windows, normalized finding annotations (`reviewer_label`, dismissal reason), draft comment threads, and audit events. Use short transactional schema initialization and keep existing JSON finding/revision snapshots readable.
3. **Checker/AI reliability:** introduce a shared checker protocol over a content object `{text, assets?}`; deterministic and AI checkers implement the same input/output contract and are composed by a pipeline. Add price formats, preferred terms, evidence-needed superlatives, and preserve approved-claim passing. The AI wrapper uses a 12-second total/request timeout, one backoff retry for invalid/transient responses, Pydantic strict JSON validation, SQLite response cache keyed by SHA-256 of normalized draft + guideline version, and atomic daily usage enforcement from `AI_DAILY_CAP` (default 300). Preserve graceful rules-only operation and the requested visible fallback sentence. Limit check requests by client IP and uploads to 2 MiB; verify PDF magic bytes. Render user text only through escaped React text nodes and escaped PDF paragraphs.
4. **Review features and analytics:** store a deterministic 0–100 Brand Health Score plus transparent severity-weight breakdown per revision; expose it in report, history, and dashboard with formula tooltip. Compare any two revisions with an inline safe diff and resolved/new finding sets. Add paste/CSV batch checking (CSV must contain `text`), bounded row counts, result table with score/top issue/status, and a route to each report. Add reviewer-only finding dismissal with reason, draft comment threads, and reviewer labels. Increment a single guideline version for every guideline mutation/reset, snapshot it with each check, and show an exact “Guidelines changed since this check. Re-run?” warning with one-click recheck.
5. **Evaluation, operations, and judge usability (active):** add a roughly 30-case labeled dataset and `/evaluation`; compute measured precision, recall, and false-positive counts separately for rules-only, AI-only, and combined predictions. When AI is unavailable, run rules-only and state that plainly; never show invented metrics. Add an audit-log page and CSV export with role/action/draft/time, excluding secrets and unnecessary comment contents, plus `/status` with database health, AI configuration/reachability state, usage/cap, guideline version, and app version; retain `/health`. Seed about 12 clearly tagged historical sample drafts (in addition to the original four editor samples) with findings. Add loading feedback, page error boundaries, existing toasts/empty states, responsive/accessibility safeguards, severity text labels, Ctrl+Enter check shortcut, and a safe “Reset demo data” action. Add routes for `/evaluation`, `/status`, and `/audit-log` and keep the route manifest synchronized. Avoid background paid AI probes: when provider reachability has not been explicitly checked, report it as unknown/not probed.
6. **Final hackathon round (current request):** first use persisted `valid` / `false_positive` labels to compute false-positive rates per finding rule; when at least three labels exist and more than half are false positives, lower that rule's future finding severity one level and show “Downgraded by reviewer feedback”. Add dashboard false-positive and recurring-issue summaries per rule and creator, with seeded examples. Next add an Admin evidence library accepting titled UTF-8 text and text-based PDF up to 2 MiB; extract/store text, seed “Cotton Certificate CC-2026-14”, show a matching document title/excerpt and suppress a supported “needs evidence” finding, or report “No evidence found”. Finally accept actual PNG/JPG ad creatives up to 5 MiB, OCR extracted text into the existing rule/AI pipeline, allow Admin to upload an approved logo, and use OpenCV matching to flag a missing logo at Medium severity with a confidence label. If OCR/OpenCV is unavailable, show a friendly nonfatal status and preserve the normal app. Keep creator analytics explicitly pseudonymous/browser-scoped unless real authentication is authorized; do not claim identity-aware multiuser analytics.
7. **Quality and handoff:** add regression tests for new behavior and retain the scripted main-flow API test; add GitHub Actions for push tests; make `.gitignore` cover `.env`, `*.db`, `node_modules`, and `dist`; verify Dockerfile, Render blueprint, and `.env.example`; update README, ARCHITECTURE, KNOWN_ISSUES, SUBMISSION, and CHANGELOG. Keep Render free-tier SQLite’s ephemeral nature explicit. Any external provider/Render/GitHub behavior not actually exercised stays documented as unverified.

## Project structure

- `backend/inkloom/main.py`: FastAPI app, `/health`, `/status` route serving, version, static assets and explicit SPA page fallback.
- `backend/inkloom/db.py`: SQLAlchemy engine/session, idempotent additive migrations, deterministic seed/reset and sample history.
- `backend/inkloom/models.py` and `schemas.py`: existing records plus AI cache/usage, rate windows, guideline state, sample metadata, revision scores, finding annotations, comments and audit events; validated request/response types.
- `backend/inkloom/api/`: guideline mutation/versioning, draft/check/revision/diff/batch/review, evaluation, audit/status and PDF endpoints.
- `backend/inkloom/services/`: `rules.py` for deterministic checks; `ai.py` for provider adapter/cache/cap; `checks.py` for the hybrid pipeline; focused reviewer-feedback, evidence retrieval, OCR/logo, score, and evaluation helpers; `pdf.py` for safe text extraction/report export; audit/rate-limit helpers.
- `backend/inkloom/data/evaluation_cases.json`: labeled, versioned evaluation set (about 30 cases).
- `frontend/src/App.tsx`: route-backed workspace pages and current core flow; smaller components/utilities for error boundaries, score, diff, batch, comments, annotations, evaluation and status.
- `frontend/src/api.ts`, `types.ts`, `styles.css`: same-origin typed API, contracts, and existing responsive textile-ledger design extended consistently.
- `frontend/public/manus-routes.json`: complete static declaration for `/`, `/new`, `/batch`, `/report`, `/review`, `/dashboard`, `/history`, `/guidelines`, `/evidence`, `/evaluation`, `/audit-log`, and `/status`.
- `tests/`: isolated temporary-SQLite pytest coverage and scripted end-to-end API flow; `.github/workflows/tests.yml` runs it on push.
- Root delivery files: `Dockerfile`, `render.yaml`, `requirements.txt`, `.env.example`, `.gitignore`, README, architecture/issues/submission/changelog, TODO, and this plan.

## Design continuity

Keep the chosen **Textile lab ledger** direction rather than restyling the product. It uses modern editorial/Swiss information hierarchy with subtle textile-swatch and evidence-ledger motifs: warm paper surfaces, charcoal ink, deep evergreen for trust, muted amber for review attention, red only for high-severity risk; persistent left rail on desktop and compact mobile navigation; fine stitched dividers, numbered revisions, evidence chips; direct, supportive, evidence-led microcopy; system sans controls and editorial serif headings; restrained 140–180 ms transitions and reduced-motion support. Brand essence: a precise, calm, accountable review desk for teams checking content before it goes live. Signature brand color remains evergreen `#1F5B4B`. Use no new decorative imagery; this is an internal workflow tool.

## Constraints and assumptions

- No real authentication or security boundary is added; role labels remain simulated and this is suitable only for public demo data.
- No real authentication, social publishing, or multilingual analysis is in scope. OCR/logo and evidence-library features must report when optional native dependencies are unavailable rather than crash.
- User-supplied provider keys remain runtime-only; missing/unreachable AI must never break the rules-only path. AI evaluation uses only measured results and may be unavailable when no provider is configured or the daily cap is reached.
- Preserve the current Webdev project and canonical Manus repository. No public release, GitHub transfer, user-remote push, Render deployment, secret entry, or production data mutation is authorized by the current request.
- Render free local SQLite is ephemeral; README must give the exact persistent-disk setting if durable state is required.
